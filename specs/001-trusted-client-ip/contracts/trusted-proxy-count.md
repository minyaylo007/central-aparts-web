# Contract: TRUSTED_PROXY_COUNT, `_visitor_ip()` и журнальные строки

Внешних HTTP-интерфейсов фича не добавляет и не меняет: маршруты `/api/quote/<apt_id>` и
`POST /api/coupon/check` принимают и отдают то же, что раньше. Меняется только значение
исходящего заголовка X-Forwarded-For к бек-офису. Контракт ниже — для исполнителя и тестов.

## 1. Настройка окружения

```text
TRUSTED_PROXY_COUNT   не задана | "" | 0 | целое ≥ 1
```

Семантика и разбор неверных значений — [data-model.md](../data-model.md), раздел «Настройка».
Где задаётся: `/etc/central-aparts-site/site.env` на коробке (образец —
`deploy/site.env.example`); на Lambda не задаётся (вне фичи).

## 2. Функция `_visitor_ip() -> str` (app.py)

Вызывается внутри запроса ровно один раз в каждом из двух маршрутов и передаётся как
`client_ip=` в `get_client().get_quote(...)` и `get_client().check_coupon(...)`.

| # | Режим | X-Forwarded-For | REMOTE_ADDR | Результат | WARNING |

## 3. Журнальные строки (logger модуля `app`)

| Когда | Уровень | Текст (формат `ключ=значение`) |
|---|---|---|
| импорт `app.py`, режим default | INFO | `client_ip_mode mode=default` |
| импорт, N = 0 | INFO | `client_ip_mode mode=ignore_header` |
| импорт, N ≥ 1 | INFO | `client_ip_mode mode=trusted_proxies n=<N>` |
| импорт, настройка неверна | ERROR, затем INFO `mode=default` | `client_ip_config_invalid env=TRUSTED_PROXY_COUNT fallback=default` |
| откат на запросе | WARNING | `client_ip_fallback reason=<no_header\|fewer_than_n\|not_ip> elements=<int>` |
| откат `no_header` с петли (23.10.2026: наша проверка curl мимо Caddy; Caddy ставит заголовок каждому гостю) | INFO | тот же текст |

Инварианты:
- ни в одной строке нет адреса (ни гостя, ни соединения), содержимого X-Forwarded-For и сырого
  значения настройки;
- на запрос не больше одной строки `client_ip_fallback`; `exc_info` не передаётся;
- существующие строки `quote …` и `coupon_check …` не меняются.

## 4. Что не меняется (регрессионные гарантии)

- `request.remote_addr`, `request.scheme`, `request.host`, `request.url_root` — как до фичи;
  `app.wsgi_app` не оборачивается (в частности, не является `ProxyFix`).
- Тела `/robots.txt` и `/sitemap.xml` при одинаковом запросе совпадают при любом значении
  настройки, в том числе при подделанных `X-Forwarded-Proto` и `X-Forwarded-Host`.
