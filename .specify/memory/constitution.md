# Constitution — central-aparts-site (🌐 сайт бронирования)

При конфликте действуют правила владельца и CLAUDE.md проекта. Этот файл их не
копирует — ссылается и фиксирует то, что проверяют /speckit-plan, /speckit-analyze и /speckit-converge.

## Источники правил (прочитать до работы)
- Правила владельца и машины (чужие проекты, прокси, порты, процессы, реестр портов) — внутренние,
  вне публичного репозитория; у сессий они подключены через CLAUDE.md.
- CLAUDE.md в корне репозитория — правила и контекст проекта.

## Инварианты (MUST; нарушение — CRITICAL в analyze)

### I. Тесты до пуша
Каждое изменение поведения идёт с тестом. Перед пушем MUST быть зелёными: `python -m pytest tests/ -q` (venv с requirements-dev.txt)
и Playwright-смока `cd e2e && npx playwright test` (fake, e2e/README.md).
Сборки нет (Flask без бандлера) — шага сборки перед пушем нет. Красные тесты не пушатся и не «чинятся» пропуском.

### II. Секреты и персональные данные — никогда
Ключи, пароли, токены, персональные и медицинские данные MUST NOT попадать в код, логи, коммиты,
спеки, тесты и отчёты. Секреты — только в .env вне git; в репозитории — .env.example.
В спеках, фикстурах и примерах — только синтетика.

### III. Никаких новых зависимостей от AWS
Новый код MUST NOT добавлять зависимостей от AWS (SDK, S3, SES, SQS, Lambda, Cognito, RDS и т. п.).
Замена — сервисы на своей машине. Облачных баз (Supabase cloud, Firebase, Neon…) не заводим.

### IV. Сеть: только 127.0.0.1 и свой порт
Процесс слушает MUST только 127.0.0.1 и только порт проекта из реестра портов: 8004 (gunicorn — сервис
сайта), 8010 (gunicorn смоки и замера нагрузки).
Общий обратный прокси машины не запускается, не останавливается и не перезагружается; его admin-порт не трогается ничем.

### V. Чужое не трогать
Чужие проекты, конфиг общего прокси, чужие юниты, контейнеры и порты —
только чтение, где разрешено. Процессы гасятся только по PID, никогда по имени.

### VI. Git
Коммит после каждого законченного шага, git add — явным списком путей, push сразу,
push --force — никогда. Основная ветка: master. Push в master запускает только CI
(.github/workflows/ci.yml: pytest + смока), в прод сам не едет; выкат в прод — только с «да» владельца.

### VII. Простота и границы
Делается то, что в spec.md, и не больше. Новая зависимость, сервис или порт — только с
обоснованием в plan.md (Complexity Tracking) и согласием дирижёра.

## Как устроен SDD в проекте
- SDD — фича больше ~1 дня или затрагивает данные, деньги, вход, безопасность.
  Мелкие правки и эксплуатация — обычным заданием, без specs/.
- Фичи — specs/NNN-short-name/; номер назначает дирижёр, short-name латиницей.
- Спецификатор коммитит только specs/NNN-x/; исполнитель — коммит после каждой фазы tasks.md.

## Специфика проекта

- Что это: публичный сайт бронирования Central Square Apartments (Черновцы); данные — только
  через API бек-офиса, своей БД нет (CLAUDE.md §1, §3).
- Стек: Flask + Jinja2 + requests, gunicorn; i18n — translations.py; JS — static/main.js (CLAUDE.md §2–§4).
- Критичные потоки — не менять без отдельной спеки: бронирование и оплата (/book → Монобанк,
  туристический сбор, страница подтверждения), купон постоянного гостя, котировка цены (CLAUDE.md §7, §9).
- Прод и выкат: своя машина за обратным прокси (gunicorn 127.0.0.1:8004); infra/template.yaml и
  wsgi_adapter.py — лишь откат на AWS Lambda. Процесс выката — во внутренних документах, не в этом репо.
- Особое: UI только по-украински, строки — в translations.py; в `<script>` — только `| tojson`;
  ошибки API — страница public_error.html (CLAUDE.md §1, §9). Номера спек сайта назначает
  дирижёр сайта.
