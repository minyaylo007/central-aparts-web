## Запуск

Разово на машині (root не треба; якщо системні бібліотеки Chromium уже є —
`install-deps`/`sudo` НЕ запускати):

```bash
python3 -m venv ~/venvs/central-aparts-site          # якщо ще нема; команди python нема — python3
~/venvs/central-aparts-site/bin/pip install -r requirements-dev.txt   # застосунок + pytest + ruff, як у CI
cd e2e && npm ci && npm run browsers                 # chromium → ~/.cache/ms-playwright-central-aparts-site
npm run browsers:where                                # який chromium візьме смока
```

**Браузери сайту — свої, не в `~/.cache/ms-playwright`.** Той каталог спільний для всіх проєктів
користувача, і установник одного зносить «чужі» версії іншого (11.09 установка бек-офісу знесла
наш chromium). Смока бере `~/.cache/ms-playwright-central-aparts-site` (або
`SITE_PLAYWRIGHT_BROWSERS_PATH`) — поза git, один на всі worktree сайту (~660 МБ, а не по копії в кожному). Шлях задає `browsers-env.cjs`: його
підключають `playwright.config.ts` (тож звичайний `npx playwright test` іде туди сам) і npm-скрипти.
Лише поза CI і лише якщо `PLAYWRIGHT_BROWSERS_PATH` не задано ззовні — так його й переозначають.
Голий `npx playwright install` конфіг не читає і поставив би в `~/.cache` — ставити лише
`npm run browsers`. Версія прибита: `@playwright/test` **1.63.0** точно (chromium 1243) — підняли
версію, повторіть `npm run browsers`.

Прогін (з теки `e2e/`):

```bash
ss -ltnp | grep ':8010'          # порожньо? 8010 — порт смоки, чужий процес — стоп
npx playwright test --grep @critical      # за замовчуванням: 25 з 44 сценаріїв
npx playwright test               # fake: без мережі, так само, як у CI
SMOKE_BACKEND=live npx playwright test   # live: справжній бек-офіс, лише читаючі сценарії
npx playwright test tests/01-delivery.spec.ts --project=desktop   # одна група / один проєкт
```

**Тег `@critical` (22.09.2026).** Сценарій стереже гостя, гроші або доступність: групи
2 (календар і ціни), 3 (купон) і 4 (бронь до Монобанку) цілком — тег стоїть на
`test.describe`; плюс точково каркас підміни (`00-harness`), `/health` і головна з групи 1.
Група 5 (мова, мобільний, галерея) — у повний набір. Повна смока — 85 с, критична — 73 с:
різниця мала, бо найдовші сценарії і є критичні, тож перед пушем ганяємо повну.

Playwright сам піднімає gunicorn на `127.0.0.1:8010` (`webServer` у `playwright.config.ts`) і
сам гасить його (SIGTERM своєму PID) наприкінці. Якщо щось лишилось — `ss -ltnp` → `kill -TERM <pid>`.
Ніколи `pkill`/`killall`: на машині живуть чужі gunicorn.

8004 — сервіс сайту (користувацький юніт systemd), смока туди свій сервер не піднімає. Прогін
проти сервісу — лише читання: `SMOKE_BASE_URL=http://127.0.0.1:8004 SMOKE_BACKEND=live npx playwright test`.

`npx playwright show-report` тут НЕ запускати — він слухає порт (9323), якого нема в реєстрі.
Звіт — статичний `playwright-report/index.html`, трейси невдалих тестів — у `test-results/`.

## Змінні оточення

| Змінна | За замовчуванням | Що робить |
|---|---|---|
| `SMOKE_BACKEND` | `fake` | `fake` — сайт із підмінним бек-офісом; `live` — справжній `BACKOFFICE_URL` |
| `SMOKE_BASE_URL` | `http://127.0.0.1:8010` | адреса сайту. Задана — свій сервер НЕ піднімається (прогін по коробці) |
| `SMOKE_BACKOFFICE_URL` | `https://cv.central-aparts.store` | бек-офіс для live (сайт і сторож) |
| `SMOKE_HOSTS` | порожньо | імена для сценаріїв 1–2, через кому. Порожньо — вони skip |
| `SMOKE_CANONICAL_HOST` | `www.central-aparts.store` | канонічне імʼя (`SITE_URL`) |
| `SMOKE_PYTHON` | `~/venvs/central-aparts-site/bin/python`, інакше `python3` | чим запускати gunicorn |
| `SMOKE_FAKE_DELAY_MS` | `0` | лише замір навантаження: кожне звернення до підміни чекає N мс (`e2e/fake_transport.py`). Смоку й CI не міняє |
| `SMOKE_FAKE_REAL_CLIENT` | не задано | лише замір: `1` — сайт ходить через справжній `BackofficeClient` із TTL-кешем, підмінено лише HTTP-сесію. Самоперевірка: `python -m pytest e2e/test_fake_transport.py -q` |

`PUBLIC_API_KEY` смоці не потрібен і в сервер під тестом передається **порожнім** навмисно:
читаючі ручки бек-офісу відкриті задумом, а пишучі в live не запускаються.

## Режими

**fake** — `e2e/fake_wsgi.py`: справжній `app.py` під справжнім gunicorn, але
`api_client.set_client(FakeBackofficeClient())` — мережі нема. Так ганяє CI.

**live** — `wsgi.py` проти бойового бек-офісу. Лише **читаючі** сценарії (каталог, квартира,
доступність, котирування, ціни). Сценарій, що пише в бек-офіс (перевірка купона, `POST /book`),
на початку тіла викликає:

```ts
import { test, expect, skipWritesInLive } from './fixtures';
test('14. телефон із правом → −500 від сервера', async ({ page }) => {
  skipWritesInLive('перевірка купона');
  …
});
```

## Сторож сторонніх запитів (обовʼязковий, обидва режими)

Кожен spec імпортує `test`/`expect` з `./fixtures`, **не** з `@playwright/test` — тоді на кожен
тест стоїть `context.route` на все:

- свій сайт → пропускається; у live — ще й бек-офіс, **лише GET/HEAD** (фото). Будь-який інший
  метод на бек-офіс із браузера — обрив і червоний тест;
- `cdn.jsdelivr.net/npm/<pkg>@<ver>/…` → віддається з `e2e/node_modules` **тієї самої версії**
  (bootstrap 5.3.3, bootstrap-icons 1.11.3, flatpickr 4.6.13, swiper 11). Flatpickr справжній, мережі
  нема. Шаблон підняв версію — підніми в `package.json`, інакше тест упаде з підказкою;
- решта (GTM, Google Analytics, пиксель Facebook, шрифти Google, Монобанк, …) → порожня заглушка
  за типом ресурсу. У бойову аналітику власника смока **не шле нічого**. Що заглушено —
  `traffic.stubbed`; навігація на чужий домен (редирект на Монобанк) дає сторінку-заглушку з
  `[data-smoke-stub="<хост>"]`, а `page.url()` лишається справжнім URL.

**Редиректи — пастка Playwright** (знайдено 11.09 групою 4): route-обробник бачить лише ПЕРШИЙ
URL, ціль редиректу — ні (навіть якщо 302 віддано через `route.fulfill`). До фіксу
`POST /book → 302 → pay.monobank.ua` відкривав у браузері **справжню** сторінку Монобанку
(вигаданий рахунок `smoke-fake-invoice`, платежу не було й бути не могло). Тепер сторож забирає
POST-навігацію свого сайту сам (`route.fetch({maxRedirects: 0})`); редирект на чужий домен
браузер не отримує — замість 302 сторінка з `location.replace(ціль)`, це нова навігація, її route
глушить. Що відповів сервер (статус, `Location`) — `traffic.offsite`. Плюс сітка: будь-який
сторонній запит, що завершився мимо route, — порушення «запит пройшов мимо сторожа в мережу».
Виняток (11.09): навігація iframe, яку браузер скасував до route (`net::ERR_ABORTED`: ленивий iframe карти на головній стартує, коли hero-пошук уже веде на квартиру), у мережу не виходила — не порушення, пишеться в `traffic.cancelled` і анотацію `cancelled_iframe`.

Фікстура `jsErrors` — неперехоплені винятки + `console.error` зі свого походження; помилки
заглушених сторонніх ресурсів не рахуються.

## Підміна бек-офісу (`e2e/fake_backoffice.py`)

Дані — константи вгорі файла, дати рахуються **від сьогодні** (смока не протухає):

| Що | Де | Значення |
|---|---|---|
| квартири A, B | `APARTMENTS`, `APT_A`, `APT_B` | 2200 і 2400 грн/ніч; A — 6 фото (колаж + лайтбокс), B — 2 |
| тестова 1 грн | `TEST_APT` = `Config.TEST_APARTMENT_IDS[0]` | лише через `/?test=1`, у списку не віддається |
| зайняті ночі | `BLOCKED_OFFSETS` | A: дні +10…+12 і +20; B: +5…+7 (виїзд у день «по» — вільний для заїзду) |
| ціни календаря | `get_rates` | 60 днів, пт/сб +300 (`WEEKEND_SURCHARGE`) |
| котирування | `get_quote` | ночі × ціна дня + збір `TAX_PER_GUEST_NIGHT`=**37** × ночі × гості |
| купон | `COUPON_PHONES` | `+380000000500` має право; −500 від суми ≥ 4000, інакше `coupon_min_total` |
| оплата | `PAYMENT_URL` | `https://pay.monobank.ua/smoke-fake-invoice?ref=SMOKE0001` (у браузері — заглушка) |

Збір навмисно **37**, а не 48 (константа в `main.js`) і не 26 (бойовий на 11.09): якщо віджет
покаже 48-кратну суму — значить JS рахує сам, а не бере з сервера.

Невалідне котирування (минуле, 0 ночей, гості поза 1..4) → `None` → сайт віддає 400, як бойовий.
Бронь на зайняті дати → `dates_unavailable`; `coupon_expected` без права → `coupon_unavailable`.

Що сайт передав у підміну — `GET /__fake__/state` (є лише в процесі смоки, не в `app.py`):
`last_booking` (поля форми `/book`, включно з `coupon_phone`/`coupon_expected`),
`booking_requests` (усі форми `/book` за прогін, по порядку), `last_quote`, `last_coupon_phone`,
`bookings`, `ids`. Сервер один на весь прогін (`-w 1`), тести паралельні (desktop і mobile
одночасно) — `last_booking` перезаписує сусід; шукай своє в `booking_requests` за унікальним
імʼям гостя (`guestName()` у `tests/helpers.ts`).

Додати дані: допиши константу/квартиру в `fake_backoffice.py`, не ламаючи наявних значень —
на них спираються інші групи. `tests/conftest.py` (`MockBackofficeClient`, 90 pytest-тестів) —
окремий мок, його не чіпати заради смоки.

## Групи 1–2: сценарії лише для коробки

Сценарії 1 (три імені + канонічне) і 2 (HTTP→HTTPS, сертифікат) на localhost не перевірити —
без `SMOKE_HOSTS` вони skip. **Не запускати їх проти бойових доменів, поки там CloudFront**:
предмет перевірки — коробка. На коробці:

```bash
SMOKE_BASE_URL=https://www.central-aparts.store \
SMOKE_HOSTS=central-aparts.store,www.central-aparts.store,v2.central-aparts.store \
SMOKE_BACKEND=live npx playwright test
```

Канонічного **редиректу** на зворотному проксі зараз нема: усі три імені віддають
сайт, канонічне — лише `<link rel="canonical">` на `SITE_URL`. Сценарій 1 це й перевіряє, а
редирект, якщо його додадуть, дозволено лише на те саме або канонічне імʼя.

## Група 2: календар і котирування (`tests/02-calendar.spec.ts`)

Дати й суми **не хардкодяться** і формула котирування в тесті **не повторюється**: зайнятість
береться з `/api/availability`, ціни — з `/api/rates`, суми — з перехопленої відповіді
`/api/quote` (`waitQuote` → `expectServerQuote`). Тому 6–11 ідуть і в live — лише GET, без
купонного телефону (`quoteJson` це перевіряє). Дані підміни (збір 37, пт/сб +300) — лише у fake;
hero-пошук на головній (перетин зайнятостей A і B) — лише fake.

Flatpickr — **тільки справжні кліки**: `calendarFor(page, input)` відкриває календар поля,
`dayCell(input, cal, iso)` знаходить день за `aria-label` (формат бере в самого інстансу) і гортає
вперед; `pickStay` — заїзд + виїзд. Інстанс `_flatpickr` лише читаємо. Усе це — у
`tests/helpers.ts` (спільне для груп 2–5), разом із `waitQuote(…, couponPhone?)`,
`expectServerQuote`, `tr(key)` (текст із `translations.py`, не своя копія) і `fakeState`.

**Відома находка, не чинити (рішення власника):** `static/main.js` рахує миттєву оцінку до
відповіді сервера зі збором **48** (рядки з `TOURIST_TAX`). Сценарій 10 тримає відповідь
`/api/quote` (`page.route` + ворота), читає, що бачить гість, і пише це в анотації
`guest_sees_before_server` і `quote_ms` (видно у виводі прогону й у HTML-звіті) — тест від цього
не падає, перевіряється лише підсумок після відповіді.

Пастка: `toBeDisabled()` на `<option disabled>` каже «enabled» — дивитись `toHaveJSProperty('disabled', true)`.

## Група 3: купон постійного гостя (`tests/03-coupon.spec.ts`)

Усі сценарії пишуть (перевірка купона має ліміт і журнал у бойовому) → `skipWritesInLive`.
Телефони — з підміни: `+380000000500` має право, `+380000000013` — ні.
Код оператора `00` навмисний: він не виділяється, номер не може бути чиїмось, а `uaPhoneShape` у `main.js` усе одно бачить валідні 12 цифр.

- **Задум C6, не баг:** блок купона стоїть ПІД сумою і згорнутий разом із нею (`.coupon-field--priced`,
  `0fr`), доки нема `.is-priced`. До вибору дат кнопку купона не натиснути (Playwright бачить її
  «visible», але клік перехоплюють сусіди) — спершу дати.
- Шлях без дат (`POST /api/coupon/check`) реальний лише після того, як гість переніс заїзд за старий
  виїзд: виїзд скинуто, сума «протухла» (`is-stale`), блок купона на місці. Так його й відтворює 13.
- З датами «Застосувати» — одна `/api/quote?coupon_phone=`: `waitQuote(page, id, stay, guests, phone)`;
  `null` — лише запит БЕЗ купона.
- Невідомий телефон: у котируванні **жодного** `coupon_*`; статус — `tr('coupon_not_found')`.
- Сума < мінімуму (одна ніч): `coupon_applied:false` + `coupon_min_total`, рядка −500 нема,
  `#f-coupon-expected` порожній, телефон лишається в `#f-coupon-phone`.
- 15: після −500 main.js ставить `#f-coupon-expected=1` і підставляє телефон купона в `#w-phone`;
  у підміну доїжджає `coupon_phone` + `coupon_expected: "1"`, рахунок — на суму зі знижкою.

## Група 4: бронювання до Монобанку (`tests/04-booking.spec.ts`)

СТОП на редиректі: заглушка `[data-smoke-stub="pay.monobank.ua"]`, жодних платежів. Пишуть усі,
крім 16 (`/?test=1` — лише читає, іде й у live: тестова квартира визначається різницею каталогів
`/` і `/?test=1`, у fake ще й звіряється з `ids.test_apt`). У live, якщо тестової квартири з
`TEST_APARTMENT_IDS` у бек-офісі нема (з 22.10.2026 — 404), 16 після перевірки `/` іде в skip
з причиною; заводити її в бек-офісі — не справа смоки.

- 17: `required` на `#w-name`/`#w-phone` — браузер не відправляє форму (фокус на першому порожньому,
  POST /book не йде, кнопка не зависла в «Створюємо платіж…»). Серверна гілка — `page.request.post`
  без телефону (та сама cookie сесії) → 302 → флеш `tr('fill_all_fields')` на сторінці квартири.
- 18б: календар зайняте не дає вибрати, тому «інший гість устиг раніше» відтворено підміною значень
  прихованих `#f-check-in/#f-check-out` перед натисканням — відмовити мусить сервер. Флеш
  `dates_unavailable`, дат в адресі й у формі нема, кнопка неактивна.
- 19 — «назад» із Монобанку. **bfcache під смокою НЕ працює** (`pageshow persisted=false`): Playwright
  завжди запускає Chromium з `--disable-back-forward-cache` (його типові прапорці), Chromium у
  `Page.backForwardCacheNotUsed` так і каже — `BackForwardCacheDisabledByCommandLine`,
  `…DisabledForDelegate` (анотація `bfcache`). Прибрати прапорець не допомагає (перевірено
  `ignoreDefaultArgs`): headless shell сам відмовляє — `BrowsingInstanceNotSwapped`,
  `BackForwardCacheDisabledForDelegate`. Тест чесно перевіряє обидві гілки: з bfcache — та
  сама серверна сума, кнопка робоча й повторно відправляє; без нього — свіже завантаження без суми
  «з минулого», кнопка неактивна до вибору дат, дати → нове котирування. Гілка bfcache у CI поки
  не виконується — перевіряти руками в справжньому браузері.
- `/booking-confirmed?ref=` — лише читаємо: деталі броні з підміни, посилання «Продовжити до
  документів» веде на `BACKOFFICE_URL/pay/<ref>` (не натискаємо).

**Находка 11.09, полагоджено 11.09 (регресійний тест у `04-booking.spec.ts`):** `flatpickr.min.css`

## Група 5: мова, мобільний, галерея (`tests/05-lang-mobile-gallery.spec.ts`)

Усе лише читає (GET сторінок, `/lang/<code>` міняє тільки cookie сесії, котирування — GET), тому йде й
у live. Кількість фото береться з того, що сервер реально віддав (слайди `.apt-hero-slide` в HTML):
квартира з ≥ 2 фото для swiper, з ≥ 5 — для колажу; нема такої в live — skip з причиною.
Сценарій, привʼязаний до вьюпорта, на «чужому» проєкті — skip `лише проєкт mobile/desktop: …`
(`onlyProject()` у spec).

- **20, мова.** Перемикач — видиме з двох `a[href="/lang/en|ua"]` (мобільна `.lang-mobile-btn` або
  десктопна в навігації). `/lang/<code>` → редирект на referrer. Тексти — `tr(key, lang)`; мову
  видно ще й з `<html lang>` (`uk`/`en`) і `window.LANG` (`ua`/`en`). Пастка ua → uk: сесія й `LANG` —
  `ua`, `uk.js` Flatpickr підключено лише для `ua` (`flatpickr.l10ns.uk`), у EN — вбудована англійська
  локаль (тиждень з неділі). `/lang/uk` мову **не** міняє — «uk» не мова сайту.
- **21а, горизонтальний скрол.** `scrollWidth ≤ clientWidth` на головній і квартирі в ua і en, плюс
  `innerWidth` = 390: ширший вміст мобільний Chromium «вміщує», зменшуючи сторінку, і тоді
  `scrollWidth` сам по собі нічого б не показав.
- **21б–в, липка панель.** `.visible` ставить IntersectionObserver, коли ВЕСЬ віджет поза екраном;
  `.kbd` ховає її, поки відкритий календар або фокус у полі віджета. Панель зсунута `transform`, а не
  схована: дивитися `toBeInViewport()`, не `toBeVisible()`. Без дат `#stickyBtn` прокручує до віджета й
  сам відкриває календар заїзду; з датами — показує серверну суму (`#stickyPrice`) і веде до
  порожнього `#w-name`, форму не відправляє. `POST /api/ux` у цей час — UX-телеметрія сайту
  (`track()`, лише рядок у лозі сайту), це не запис у бек-офіс.
- **21г, swiper.** Свайп — справжнім дотиком через CDP `Input.dispatchTouchEvent` (`swipe()` у spec,
  лише Chromium). Жест із CDP триває > 300 мс, swiper вважає його «довгим» і гортає лише від 50%
  ширини — тому `swipe(…, ±0.7)`; на пів екрана він чесно відпружинює. Стрілки `.swiper-button-*`
  на мобільному видно. `loop: true`: з першого фото «назад» — останнє. Номер кадру — `data-index`
  слайда (DOM-порядок у loop не гарантований).
- **22, лайтбокс (desktop).** Відкривається кнопкою колажу `[data-lightbox-open]` (фото 1) або плиткою
  (своє фото). Кнопки — `getByRole('button', {name})`: підписи — з `translations.py` (`lightbox_*` →
  `LIGHTBOX_TXT` у `public_apartment.html`), у тесті — `tr()`.
  Стрілки й кнопки йдуть через край в обидва боки (`nav()`: `(idx + d + n) % n` — перевірено по коду),
  Tab/Shift+Tab ходять по колу всередині, Escape і клік по тлу закривають, фокус повертається на
  кнопку колажу, `body` знову гортається.

**Находки 11.09, полагоджено 11.09 (регресійні тести 22б, 22в у `05-…`, лише desktop — колаж ≥992px):**
- **22б** — при відкритті лайтбокса фокус лишався на кнопці ПІД ним: `open()` кликав `focus()`, поки
  `.lightbox` ще `display:none` (клас `.open` — у наступному `requestAnimationFrame`). Тепер фокус на
  «Закрити» ставиться в тому ж `requestAnimationFrame`, одразу після `.open`.
- **22в** — підписи лайтбокса («Закрити», «Попереднє/Наступне фото», alt «фото N з M») були зашиті в
  `main.js` українською. Тепер — ключі `lightbox_*` у `translations.py`, мова сторінки. alt =
  «<назва> — <підпис>»: мовою сторінки перевіряється лише підпис (`tr('lightbox_photo_of','en')`);
  назва — дані бек-офісу (живий віддає її українською й для EN), звіряється з h1 `.apt-detail-name`.
